# Skill Selection Rules

## Objective

Select skills based on the actual task, not simply because they are available.

## Selection Process

1. Identify the user's intended outcome.
2. Classify the task by design discipline.
3. Select one primary skill that best matches the task.
4. Add supporting skills only when necessary.
5. Check for conflicting instructions.
6. Follow the global orchestration rules.
7. Evaluate the result against the task requirements.

## Selection Principles

- Relevance over quantity.
- One clear primary skill wherever possible.
- Supporting skills must add distinct value.
- Avoid activating overlapping skills without a clear reason.
- Preserve project-specific instructions and constraints.
- Do not assume that a skill is authoritative simply because it is installed.

## Conflict Handling

When instructions conflict, use the hierarchy defined in the global orchestration rule. Do not silently combine contradictory requirements.

## Limitations

Skill selection does not guarantee output quality. Results still require human review, testing, and design judgment.
